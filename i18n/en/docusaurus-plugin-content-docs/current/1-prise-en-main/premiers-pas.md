Choose your starting point based on what you want to track. Each step points to the section that details it.

## Tracking a team’s flow

1. Import the team’s Jira project or board, or an Excel file. → Part 2, section [2.2 Importing a product](../2-produits/importer-produit.md).
2. Do the initial configuration: issue types and workflow (the workflow stages). → Part 2, section [2.3 The initial configuration](../2-produits/premiere-configuration.md).
3. Read the product dashboard. → Part 2, section [2.4 The dashboards](../2-produits/produit-tableaux-de-bord.md).
4. Go further with the charts, the forecast and the 360 Analysis. → Part 2, sections 2.5 to 2.8.

## Tracking software delivery

1. Import a DORA view from GitHub or GitLab. → Part 4, section 4.3 Importing a DORA view.
2. Read the DORA Metrics and their performance level. → Part 4, sections 4.1 and 4.4.
3. Link the view to the same team’s product, to move from one to the other. → Part 4, section 4.7 A view’s settings.

## Assessing a team’s maturity

1. Create an assessment template, or use an existing one. → Part 6, section 6.2 Templates.
2. Create the team’s assessment and link it to its product. → Part 6, section 6.3 Team assessments.
3. Enter a first measurement with the team, then track its progress. → Part 6, section 6.3.

## Scaling up to several teams

- Flow Metrics: create a program from the teams’ products. → Part 3.
- DORA Metrics: create a DORA program from their views. → Part 5.
- Assessments: create an assessment program. → Part 6, section 6.4.

## Going further

- Ask Alice to analyze a chart or a sprint. → Part 7.
- Build your own dashboards. → Part 2, section 2.9 Settings.
- Query your data from Claude with MCP access. → Part 8, section 8.5.
